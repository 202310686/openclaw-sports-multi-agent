# 简历与讲解

## 项目标题

基于 OpenClaw 的少儿体育培训 Multi-Agent 业务自动化原型

## 可据实使用的描述

- 将模拟体育培训业务拆解为招生、课程、教练与主管四个独立 OpenClaw Agent，使用 Node.js 实现可追踪的确定性多智能体工作流。
- 实现咨询画像提取、知识约束课程建议、训练反馈和主管汇总，自建本地展示界面支持阶段状态、执行证据、人工编辑审核与 JSON 导出。
- 为原型增加结构校验、工具权限限制、单任务并发、超时取消、隐私筛查和离线历史回放，并编写自动化测试与复现文档。

## 要能回答的问题

1. 为什么使用多个 Agent？不同角色的约束独立，可检查单阶段结果与责任；但也增加成本和延迟，本项目未证明它比单模型更准确。
2. 谁在编排？Node 工作流代码，不是主管自主派遣；主管负责计划和最终综合。
3. 真实调用如何证明？CLI 返回的 receipt、Agent/session ID、模型、耗时和结果，不靠回答中“我调用了”这样的声明。
4. 如何避免幻觉？有限知识来源、未知项显式标记、字段规则、输出审核；不是保证模型永不编造。
5. 为什么不接企业微信？真实客户发送需要权限、审计、隐私和审批设计，原型只生成草稿。
6. 项目有什么局限？固定流程、单用户、模拟数据、无 CRM/排课/自动发送，无业务收益实测。

不要写企业级、真实落地、转化率提升等未验证结论。能复现和解释自己的代码比堆术语重要。
